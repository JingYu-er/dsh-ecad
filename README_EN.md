# dsh-ecad

[![license](https://img.shields.io/github/license/JingYu-er/dsh-ecad)](LICENSE)
[![version](https://img.shields.io/badge/version-0.1.2-orange)](https://github.com/JingYu-er/dsh-ecad)

Hardware-side DSH plugin for STM32 projects: schematics, PCB, fabrication files, cost and checks. It is the sibling of the firmware plugin `dsh-stm32`; the two exchange facts through `<project>/dsh/mcu.json`, their tool names do not overlap, and both can be installed together.

Scope runs from "write a `circuit.tsx`" to "hand out Gerbers and a BOM": parts and footprints come from the KiCad official libraries (falling back to the LCSC product page), schematic and PCB are generated by tscircuit, placement and routing use KiCad tooling, and the checks and cost figures are computed here.

## Split with dsh-stm32

| | dsh-stm32 (firmware) | dsh-ecad (hardware) |
| --- | --- | --- |
| Owns | toolchain, `.ioc` transactions, project creation, generate, build, flash, debug, UART/RTT | parts and footprints, schematic, PCB, fabrication files, BOM/cost, EMC/thermal/impedance checks |
| Schematic | read-only: parse, pin table, rule check, review, `.ioc` draft | read-write: generate, hand-drawn layer, absorb edits back into the source |
| Fact file | writes `dsh/mcu.json` (`dsh-mcu/1`) | reads `mcu.json`; `board.json` is the planned reverse channel |

The settings page has a read-only **Circuit design toolchain** section: KiCad (`kicad-cli`/`bun`/`python`), the shared tscircuit runtime, KiCadRoutingTools, poppler and KiCad IPC (`kipy`) readiness, each with the fix for whatever is missing. It never installs anything or edits projects.

Both plugins vendor the shared core (KiCad parsing, project layout, toolchain discovery, atomic writes) instead of depending on a common package.

## Capabilities

- **Schematic**: parse KiCad 10 `.kicad_sch` (instance transforms, sheets, nets), emit SVG and a netlist diff; the hand-drawn layer supports wires, labels, cloning, moving and placing new parts, stored in the drawing itself rather than the generated directory.
- **PCB**: placement from the `circuit.json` netlist (MCU centered, connectors on edges, small parts next to the large one they serve); routing via KiCadRoutingTools; local edits via the official KiCad IPC when the editor is running.
- **Fabrication**: Gerber and drill review as SVG; STEP/GLB export; DXF outline and mounting holes; JLC process floors written into `.kicad_dru`.
- **Checks**: ERC/DRC/DFM, netlist-to-PCB gate (including hand-drawn differences), EMC (current capacity, return path coverage, crosstalk, differential spacing), stackup and impedance, power budget, 3D model coverage.
- **Cost**: BOM grouping (primary LCSC part plus alternatives), on-demand LCSC price and stock lookup, component cost total.
- **Parts**: search by MPN, parameters or LCSC code; import a footprint by code (KiCad library first, LCSC page as fallback); the 3D model referenced by the footprint is copied into the project too.

## Install

```bash
dsh plugin --profile desktop add dsh-ecad
```

Fully quit and restart DSH afterwards; the plugin layer is only loaded at process start.

- Verify: `dsh plugin --profile desktop why dsh-ecad` reports `0.1.2`
- Remove: `dsh plugin --profile desktop remove dsh-ecad`, then restart

External dependencies (each tool states what is missing):

| Dependency | Used for | Without it |
| --- | --- | --- |
| KiCad 10 (`kicad-cli`, `pcbnew`, official libraries) | project generation, ERC/DRC, Gerber, 3D, footprint and symbol libraries | build and checks unavailable |
| Node.js + shared runtime (tscircuit) | compile `circuit.tsx` into a KiCad project | first build reports how to install; lives in `~/.dsh-ecad/ecad-runtime`, one copy per machine |
| KiCadRoutingTools | autorouting | routing step is recorded as skipped, not failed |
| poppler (`pdftotext`) | datasheet text and tables | PDF tools report where to get it |

## Quick start

```
1. stm32_ecad_init        create the hardware/circuit workspace
2. write hardware/circuit/index.circuit.tsx (tscircuit source, the only writer)
3. stm32_ecad_build      produce hardware/circuit/dist/<name>/kicad/*.kicad_pcb + .kicad_sch
4. stm32_ecad_design     precheck -> build -> merge pads -> export libs -> ERC -> DRC -> DFM -> STEP -> Gerber
```

Nothing is guessed: `jlcpcb:C<code>` in the source decides the BOM part, the footprint name decides the PCB footprint. When a footprint is missing, `stm32_part_import` copies it from the KiCad library and only falls back to converting the LCSC page; if both fail the error carries both reasons.

## Hardware console

The `conversation.view` tab "硬件台" (Hardware console) sits next to the firmware plugin's debug console. Tabs: overview, events, flow chart, circuit design, faults; the console opens on "circuit design" (a board, not the firmware serial log). "Circuit design" holds board view ("2D board" / "3D solid" buttons; the solid view loads the GLB that `kicad-cli pcb export glb` writes and renders it with three.js — orbit, zoom, pan, and highlight, falling back to a box sketch without WebGL; clicking a BOM reference or a layout finding highlights it), BOM, power budget, stackup, consistency, EMC, mechanical, 3D preview, fabrication files and part search. Turns that ran design / DRC / routing / placement / layout-check / board-view also get a turn-tail summary card in the conversation; details stay in the console. Project selection is per session; the status bar shows plugin version, route count and a "newer build available" hint.

## Project layout

```
<project>/
  dsh-stm32.conf            project description, shared with the firmware plugin
  dsh/mcu.json              MCU facts written by the firmware plugin (dsh-mcu/1)
  hardware/
    circuit/                tscircuit source and output
    kicad/                  generated KiCad project (rewritten by every build)
    schematic/              hand-drawn layer, never overwritten by builds
    libs/                   imported footprints, symbols, 3D models
    out/                    Gerber, STEP, GLB, PNG, DXF, BOM
  .dsh-stm32/               workspace index and backups (shared)
```

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `DSH_ECAD_HOME` | `~/.dsh-ecad` | user-level dir: runtime, datasheet and price caches, footprint cache, evidence |
| `DSH_ECAD_ECAD_RUNTIME` | `<DSH_ECAD_HOME>/ecad-runtime` | shared tscircuit runtime |
| `DSH_ECAD_ECAD_AUTO_INSTALL` | `ask` | `auto` installs the runtime on first build |
| `DSH_ECAD_OFFLINE` | — | `1` disables network access |
| `DSH_ECAD_FOOTPRINTS` | — | override the footprint cache directory |
| `KICAD_PYTHON`, `DSH_KICAD_PYTHON` | bundled KiCad python | interpreter for `pcbnew` and IPC scripts |

The legacy `DSH_STM32_*` names are still read (the new name wins), and `~/.dsh-stm32/config.json` is used when `~/.dsh-ecad/config.json` does not exist.

## Known limits

- Autorouting is an aid: it connects everything and keeps DRC clean, but the routing quality is not hand-routed quality.
- The router follows the JLC process floor (0.127 mm for 1-2 layers, 0.10 mm for 4+ layers, minus a 0.003 mm quantization margin); a uniform 0.2 mm class needs manual widening.
- KiCad 10's IPC can write schematic items but cannot read them, so reading uses this plugin's own parser; "Update PCB from Schematic" still requires KiCad opened through the project manager.
- 3D coverage depends on tscircuit output; missing models are reported instead of faked.
- `hardware/schematic/` is the human drawing: builds never overwrite it, and it does not flow back into `circuit.tsx` unless `stm32_sch_import` is run.
- One active project per panel session.
- Most thoroughly verified on Windows.
